# Nikon Zf 现场排查清单（方案 B）

> 目标：在**不继续陷入代码细节**的前提下，先验证 Nikon Zf 当前 Wi‑Fi 模式、官方 App 前置条件、以及 Nikon Z 系列可能存在的“application mode / event fetcher / 专有会话门槛”。

---

## 最新新增观察（2026-03-14）

用户现场反馈：
- 手机连接 Nikon Zf 热点后
- **官方 App 很快连接成功**
- 但切回 PhotoSend 时，**相机热点关闭**

### 这条观察意味着什么

这是一个**很强的正向信号**，说明：

1. **普通 Wi‑Fi / TCP 层大概率没有根本问题**
   - 因为官方 App 可以快速完成连接
2. **官方 App 很可能触发了 Nikon 专有的会话状态切换**
   - 例如进入某种 application mode / 控制模式 / 独占会话
3. **相机热点关闭** 很像以下几类行为之一：
   - 官方 App 成功后，相机退出初始 AP 广播态，转入已连接控制态
   - 相机只允许官方工作流维持会话，切回第三方 App 后该状态被释放或中断
   - Nikon 当前工作流存在**单客户端独占 / 单工作流占用**

### 对当前 PhotoSend 结论的影响

这条观察会：
- **削弱**“普通 Wi‑Fi 热点没连好 / 15740 端口不对”这类假设
- **强化**以下主线：
  - Nikon 专有初始化 / application mode
  - 官方 App 先完成某些专有握手或授权上下文
  - 单客户端独占 / 会话保持机制

---

## 当前已知结论

根据现有日志与代码实验，已经可以确认：

1. `192.168.1.1:15740` 可稳定连通
2. `Init_Command_Request / Init_Command_Ack` 稳定成功
3. `OpenSession` 在以下 case 中都**5 秒内 0 字节超时**：
   - `nikon-fixed-ptpip`
   - `nikon-fixed-raw`
   - `mobile-device-ptpip`
   - `android-phone-ptpip`
   - `empty-name-ptpip`
4. 即便完全绕开 `15741`，`OpenSession` 仍被静默忽略

### 这意味着什么

当前更像：
- 相机愿意接受基础握手
- 但**不愿意为当前客户端开放真正的 PTP 会话**
- 因此主线应转向：
  - 相机当前 Wi‑Fi 模式是否真的开放控制
  - Nikon 官方 App 是否会先触发某种专有初始化
  - 是否存在 Nikon Z 系列专有的 application mode / 会话门槛

---

## 本轮排查的 3 个核心问题

### 问题 1：当前 Nikon Zf 的 Wi‑Fi 模式，是否真的允许完整控制？
### 问题 2：官方 App 能连时，是否说明还缺少 Nikon 专有初始化？
### 问题 3：官方 App 先连接一次后，PhotoSend 的表现会不会变化？

## Part A：机身菜单 / 模式核对清单

> 目标：排除“其实当前只是浏览/传图模式，而不是远程控制/PTP 控制模式”。

### A1. 核对当前 Wi‑Fi 连接入口
请在 Nikon Zf 上确认：

- [ ] 当前进入的是“与智能设备连接 / Connect to smart device”相关菜单
- [ ] 当前不是仅浏览照片/发送照片的简化模式
- [ ] 当前不是仅做一次性配网的设置页面
- [ ] 当前显示的是可供手机连接的 Wi‑Fi 热点/AP 信息

#### 预期现象
- 相机明确处于“可与手机建立控制连接”的状态

#### 异常现象
- 只有“传图/浏览”相关提示，没有“远程拍摄/连接到智能设备”含义
- 菜单更偏向照片传输，而不是控制连接

#### 判读
- 如果更像“传图/浏览模式”，那么当前很可能只开放基础发现/握手，不开放完整 PTP 控制会话。

---

### A2. 核对是否存在“远程控制 / Remote photography / 控制拍摄”相关模式
请重点确认相机端是否出现类似语义：

- [ ] Remote photography / 远程摄影
- [ ] Control / 控制
- [ ] Smart device full control / 智能设备完整控制
- [ ] 仅传送照片 / Browse only / Send only（若有，要特别记下来）

#### 预期现象
- 存在明显的“远程控制”或“智能设备控制”含义

#### 异常现象
- 只有发送、浏览、同步，不涉及控制拍摄

#### 判读
- 如果根本没有控制类入口，PhotoSend 当前“握手成功但 OpenSession 无响应”的现象就非常符合“相机模式不开放控制”的情况。

---

### A3. 核对是否有“仅允许单客户端 / 当前已被占用”的提示
请观察相机端：

- [ ] 是否提示已连接某个智能设备
- [ ] 是否提示连接被占用
- [ ] 是否必须先断开现有设备才能重新连接

#### 判读
- 如果 Nikon 官方工作流本身是单客户端独占，那么即便没有显式报错，也可能导致 PhotoSend 只能完成握手但无法进入完整会话。

## Part B：官方 App 对照实验

> 目标：验证“问题在普通 Wi‑Fi/TCP 层”还是“问题在 Nikon 官方预期的应用级状态机”。

### B1. 纯官方 App 连接实验
步骤：

1. 完全关闭 PhotoSend
2. 断开手机与相机的 Wi‑Fi 连接
3. 重启相机 Wi‑Fi 功能
4. 打开 Nikon 官方 App
5. 按官方流程连接 Nikon Zf

请记录：

- [ ] 官方 App 是否能发现相机
- [ ] 官方 App 是否能连接成功
- [ ] 官方 App 是否能进入远程拍摄/控制页面
- [ ] 官方 App 是否只能浏览或同步照片
- [ ] 官方 App 连接时，机身是否出现额外提示或确认框

#### 关键判读

##### 情况 B1-A：官方 App 也连不上
这时优先怀疑：
- 相机当前模式不对
- 相机端网络配置有问题
- 不是 PhotoSend 独有问题

##### 情况 B1-B：官方 App 能连并进入控制页面
这时几乎可以确认：
- 普通 Wi‑Fi/TCP 层没问题
- **PhotoSend 缺少 Nikon 预期的前置初始化 / 应用模式 / 授权上下文**
- 如果随后观察到**切回第三方 App 时热点关闭**，则进一步说明：
  - 官方 App 触发了 Nikon 的会话状态切换
  - 或当前工作流存在**单客户端独占 / 连接保持责任在官方 App**

##### 情况 B1-C：官方 App 只能浏览，不能控制
这时优先怀疑：
- 当前相机模式本身就不开放控制
- 不是 PhotoSend 包格式问题

---

### B2. 官方 App 成功后，立刻切回 PhotoSend 再试
步骤：

1. 先用官方 App 成功连接一次
2. 在不重启相机 Wi‑Fi 的前提下退出官方 App
3. 立即打开 PhotoSend
4. 再跑一次当前 `15740` 单通道实验

请记录：

- [ ] PhotoSend 结果是否仍然完全相同
- [ ] 是否从“0 字节超时”变成“返回错误码”
- [ ] 是否首次出现任何 `OpenSession` 响应
- [ ] 相机端是否弹出确认/切换提示

#### 判读

##### 情况 B2-A：官方 App 先连后，PhotoSend 仍完全 0 响应
说明：
- 不是简单“激活一下模式”就够
- 更像需要**专有握手 / application mode / 持续状态维护**
- 如果切回 PhotoSend 时**热点直接关闭**，则优先怀疑：
  - 官方 App 在维持 Nikon 专有会话
  - 第三方 App 没有接住官方工作流切换后的状态
  - 相机存在单客户端独占或官方 App 驱动的模式收敛

##### 情况 B2-B：官方 App 先连后，PhotoSend 行为发生变化
说明：
- Nikon 官方 App 很可能确实会先做某些关键初始化
- 后续代码主线应转向：
  - 官方客户端时序模拟
  - GUID / 应用模式 / 专有 opcode / 事件初始化
  - 会话保持 / 单客户端切换行为分析

---

## Part B+：如果“官方 App 一成功，切回 PhotoSend 热点就关闭”该怎么记

请额外记录：
- [ ] 热点是立即关闭，还是几十秒后关闭
- [ ] 手机是否自动断开 Wi‑Fi
- [ ] 官方 App 在前台时，相机端是否显示已连接/控制中
- [ ] 切回 PhotoSend 前，官方 App 是否仍在前台保持连接
- [ ] 若不切回 PhotoSend，只把官方 App 挂后台，热点是否也会关闭

### 判读

#### 情况 B+-1：只要官方 App 成功，热点就收起/关闭
最像：
- 相机从“等待配对/等待接入”切换到“已进入控制会话”
- 官方 App 驱动了 Nikon 专有状态机

#### 情况 B+-2：一离开官方 App，热点立即关闭
最像：
- 官方 App 负责维持会话心跳 / 状态保持
- 第三方 App 没有复制该保持逻辑

#### 情况 B+-3：热点关闭后，必须重新在相机上开启连接模式
最像：
- 当前 Nikon 工作流不是“任意客户端接力”模型
- 更像“一次进入、一方独占”的控制会话

## Part D：把观察结果映射回 PhotoSend 结论

### 结论映射 1：官方 App 成功控制，PhotoSend 始终 0 响应
最可能说明：
- PhotoSend 缺少 Nikon 官方预期的：
  - application mode 初始化
  - 专有配对/授权上下文
  - 官方事件获取 / 状态维持流程

### 结论映射 2：官方 App 也只能浏览/不能控制
最可能说明：
- 相机当前模式本身就没开放完整会话
- 当前重点不在代码，而在机身模式/菜单设置

### 结论映射 3：官方 App 先连后，PhotoSend 行为变化
最可能说明：
- Nikon 官方 App 确实做了某些关键初始化
- 下一轮代码实验应优先模拟官方时序和上下文，而不是继续改普通 `deviceName`

### 结论映射 3b：官方 App 一成功，切回 PhotoSend 热点就关闭
最可能说明：
- Nikon Zf 进入了官方 App 驱动的专有控制状态
- 当前链路存在**单客户端独占 / 会话保持 / application mode** 门槛
- PhotoSend 当前缺少：
  - 官方工作流触发的模式切换
  - 保活/心跳/状态维持
  - 接住官方会话后的能力

### 结论映射 4：不管怎么切模式，官方 App 和 PhotoSend 都不稳定
最可能说明：
- 先检查相机固件、Wi‑Fi 配置、单客户端占用状态
- 暂时不要把责任全部归咎到 PhotoSend
